# Nami Headset — Build Log

Technical log for context and lessons learned (not shown in-app — see `User_Log.md` for the user-facing changelog). Condensed 2026-08-18 to keep only what's still load-bearing going forward; the full session-by-session history is still recoverable from git history if ever needed.

## Lessons & gotchas (durable — read before re-hitting these)
- **NimBLE:** calling `BLECharacteristic::notify()` synchronously from inside a *different* characteristic's `onWrite` callback silently fails to transmit on this board's BLE stack — defer any notify (and anything like `ESP.restart()`) to `loop()` via a pending-flag pattern instead. Found while building BLE OTA (see "Not yet done") by checking, via serial logging, whether the firmware itself had actually attempted the send before assuming a wireless/timing problem — that check (did *this side* even try, before blaming the connection) is worth reaching for first on any "the other side never got it" bug, BLE or otherwise.
- **ESP32 board pin assignments don't transfer between variants.** Always check the specific board's `pins_arduino.h` before assuming a pin is free — some are silently reserved (JTAG, boot-strapping) even with no peripheral in this sketch using them. (Current pin choices are in "Current state" below, since they're hardware-specific and can change again.)
- **BLE stack differs by ESP32 target** — NimBLE vs. Bluedroid expose different APIs for things like RSSI reads (sync call vs. async GAP callback) and connection descriptors. Check which stack a given core/board actually ships before porting BLE-adjacent code across boards.
- **Physical strip cuts:** shortening the LED strip requires resoldering the 5V/GND/data harness to whatever's downstream onto the new cut end — and data direction matters (DO → DI). Getting this wrong leaves downstream segments completely dark with no error shown anywhere.
- **Partition schemes must be explicit and matched to the board** — an omitted or mismatched scheme silently reverts to a different partition table than what's actually flashed, risking a boot/partition mismatch. Available scheme options differ per board (current FQBNs are in `CLAUDE.md`'s Firmware toolchain section).
- **Odd LED counts:** any pattern splitting a strip into two mirrored halves must round the midpoint *up*, not down (`(count+1)/2`), or the exact center LED never gets covered by either half — full reasoning is commented at the `half = (count + 1) / 2` lines in `Nami_Headset_LEDs_C6.ino`.
- **Distance/position math on a wrapping ring:** compute distance-from-head using the raw (unwrapped) index, and only wrap a separate index for the array access — comparing against an already-wrapped index causes a glitch right at the wrap point (a once-per-revolution blink in Waves). Full reasoning is commented in `renderWavesRing()` in `Nami_Headset_LEDs_C6.ino`.
- **CSS range slider gradients** (no code comment exists for this one — it's only written down here): paint directly on `::-webkit-slider-runnable-track` / `::-moz-range-track`, never on the `<input>` itself hoping it shows through — WebKit won't reliably paint the input's own background behind the track pseudo-element.
- **Glow/box-shadow effects** that extend beyond an element's own box (also undocumented in code) need padding room in the nearest `overflow:hidden` ancestor, or the effect gets clipped.

## Current state (as of 2026-08-18)
- **Patterns:** Solid, Breathe, Waves, Rainbow — all 4 implemented. Waves/Rainbow strip rendering is safe for odd LED counts and Waves' trail auto-caps to fit the travel distance so its edge-to-middle reset never shows a visible pop. Waves ring/strip motion is continuously interpolated (sub-pixel position, distance-based trail brightness) rather than stepping in whole LEDs, and all brightness scaling uses FastLED's video-safe scale to avoid dim colors clipping to black.
- **Connection:** auto-reconnect + ping-based fast disconnect detection + cancelable reconnect UI, all in `index.html`. RSSI subscription and pattern-switch UI logic each live in one shared helper rather than being duplicated.
- **"Last updated" stamp:** reads live from `User_Log.md`'s newest entry on page load — not a hardcoded string, so it can't go stale.
- **Color picker:** custom hue+sat square / hue slider / 4-slot picker (slot 0 locked to the firmware's default color, slots 1-3 start empty) behind a collapsible color bar. Default color is blue (`#006EFF`), matching the C6 firmware.
- **Firmware — ESP32-C6 is the sole active board** (classic ESP32 archived 2026-08-18): `Nami_Headset_LEDs_C6/Nami_Headset_LEDs_C6.ino`, FQBN `esp32:esp32:XIAO_ESP32C6:PartitionScheme=no_ota`, typically COM8. Storage usage ~42% of the 2MB app partition. `LED_PIN` is GPIO18 (D10), `STRIP_LEDS` is 69.
- **Firmware — classic ESP32, archived/reference only:** `Nami_Headset_LEDs/Nami_Headset_LEDs.ino` stays in the repo untouched but is no longer kept in sync with the C6 build. Last known-good: FQBN `esp32:esp32:esp32:PartitionScheme=min_spiffs`, COM7, `STRIP_LEDS` 68, teal/dimmer QA defaults (never updated to match the C6's later look changes).
- **Hosting:** GitHub Pages is live and confirmed working — phone loads the webpage from anywhere and controls the headset over Bluetooth directly, no local server needed. Android Chrome confirmed working.

## Not yet done
- Flash-persisted tuning params — color/brightness/speed/trail still reset to firmware defaults on reboot (only `runQA` and the on/off state survive). Analyzed, not implemented.
- Battery monitoring (fuel gauge / board swap / partial ADC read) — tabled, no decision made.
- BLE connection-interval tuning — discussed, low confidence in payoff, not implemented.
- WiFi/HTTP self-hosted rewrite for universal (incl. iOS) browser support without a workaround app — scoped, not started.
- **BLE OTA firmware updates** — built, hardware-tested, and reverted: real transfer speed measured ~900 bytes/sec (latency-bound, not bandwidth-bound), so a ~900KB image would take 15-20 minutes — judged impractical. Two real bugs were found and fixed along the way (see "Lessons" above for the NimBLE one; the other was a JS listener-registered-too-late race). The full working implementation is preserved in a `git stash` (not on `main`) — `git stash pop` restores it if revisited, so neither bug needs re-solving; only a speed fix (larger chunks and/or write-without-response) would remain.
